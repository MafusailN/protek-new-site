# CLAUDE.md

Указания для Claude Code при работе с этим репозиторием.

## Что это за проект

Концепт новой версии сайта pro-tek.pro (ООО «ПРОТЭК», Новосибирск — оптовые поставки систем
безопасности). Статический сайт без сборки и зависимостей: чистые HTML, CSS и JS.
Открывается двойным кликом по `index.html`, но полноценно — только через локальный сервер,
потому что Chrome по `file://` не передаёт параметры адреса (`?id=`, `?cat=`).

Репозиторий: <https://github.com/MafusailN/protek-new-site> (публичный).
Живая версия: <https://mafusailn.github.io/protek-new-site/> (GitHub Pages, ветка `main`, корень).

**Главный принцип проекта: никаких выдуманных данных.** Товары, цены, остатки, тексты,
логотипы и контакты выгружены с действующего сайта или с сайтов производителей. Если данных
нет — так и показываем («Фото уточняется»), а не подставляем правдоподобную заглушку.
Каждая характеристика в карточке подписана источником. Это не стилистическое предпочтение:
в оптовой торговле оборудованием придуманный параметр приводит к возврату товара и спору
с клиентом.

## Команды

```powershell
# просмотр сайта
powershell -ExecutionPolicy Bypass -File ".\tools\serve.ps1"        # http://localhost:8765
powershell -ExecutionPolicy Bypass -File ".\tools\serve.ps1" -Port 8770

# полная пересборка данных (строго по порядку)
.\tools\extract-tree.ps1        # дерево каталога            -> _source\tree.json
.\tools\select-products.ps1     # отбор товаров + фото       -> _source\catalog.json
.\tools\extract-details.ps1     # характеристики, крупные фото -> _source\details.json
.\tools\extract-brands.ps1      # логотипы брендов           -> _source\brands.json
.\tools\enrich-vendors.ps1 -Brands "Промрукав"   # данные производителей -> _source\vendor.json
.\tools\build-data.ps1          # всё вместе                 -> assets\js\data.js

# обслуживание изображений
.\tools\shrink-images.ps1                          # уменьшить до 1200px по длинной стороне
.\tools\make-cutouts.ps1 -Ids "81595,14975"        # вырезка товара без фона для подложек
```

`extract-catalog.ps1` и `extract-products.ps1` — предшественники `select-products.ps1`,
оставлены для истории. Для пересборки использовать `select-products.ps1`.

После смены подборки на диске остаются фотографии выбывших товаров. Удалять так:
собрать пути из `data.js` регуляркой `"(assets/img/[^"]+)"` и снести всё непрошенное
в `products`, `products-lg`, `vendor`. В прошлый раз это освободило 137 МБ.
Обязательно после удаления проверить, что битых ссылок нет ни в `data.js`, ни в HTML.

## Архитектура

Данные отделены от представления. Скрипты в `tools\` выгружают сырьё в `_source\*.json`,
`build-data.ps1` собирает из них единственный файл `assets\js\data.js`, страницы читают
только его.

```
assets/js/data.js    ГЕНЕРИРУЕТСЯ — вручную не править, правки затрутся
assets/js/app.js     шапка, мега-меню, поиск, корзина, карточки, характеристики, плашки
assets/css/style.css вся вёрстка, дизайн-токены в :root
assets/img/products/     карточные фото (250×150)
assets/img/products-lg/  крупные фото для галереи
assets/img/vendor/       фото с сайтов производителей
assets/img/brands/       229 логотипов брендов
assets/img/hero/         вырезки без фона для подложек
assets/img/cat/          иконки разделов с сайта
_source/                 сырая выгрузка, нужна для пересборки data.js
tools/                   скрипты выгрузки, сборки и обслуживания
```

### Что лежит в data.js

`CITIES` — шесть городов складов. **Порядок важен**: поле `s` у товара это массив 0/1
в этом же порядке (Новосибирск, Барнаул, Кемерово, Новокузнецк, Томск, Красноярск).

`MENU` — верхнее меню из 8 пунктов, снимается разбором `_source\home.html`.
Два пункта ведут на внешние сайты (`service.pro-tek.pro`, `forumprobezopasnost.ru`) —
`pageFor()` в `app.js` отдаёт их как есть, остальные ведёт на локальные страницы или
на действующий сайт.

`CATEGORIES` — 22 раздела, у каждого `sub[]` и списки `ids`.

`PRODUCTS` — около 900 товаров. Поля короткие ради размера файла (~2 МБ):

| поле | значение |
|---|---|
| `n` | название |
| `b` | бренд |
| `p` | цена числом, `null` = «по запросу» |
| `pt` | цена текстом, как на сайте |
| `img` | карточное фото, пусто = фото нет |
| `big` | крупное фото для галереи |
| `s` | массив 0/1 наличия по городам |
| `av` | наличие со сроками: `{c: город, s: stock/order, t: текст}` |
| `art` | артикул производителя |
| `code` | код товара в учётной системе |
| `sp` | характеристики с pro-tek.pro |
| `vsp` | характеристики с сайта производителя |
| `vimg` | фотографии с сайта производителя |
| `tg` | плашки: `{k: тип, t: текст}` |

`BRANDS` / `BLOGO` — 234 бренда с логотипами и числом товаров.
`PMAP` — индекс товаров по id.

### Отбор товаров: приоритет

`select-products.ps1` снимает со страницы раздела ВСЕ карточки (обычно 36) и ранжирует:

```
цена есть            +10000
городов в наличии    ×  100
фотография есть      +   10
```

Идеальный кандидат — цена, шесть городов, фото — набирает 10 610. Товар с ценой, но без
наличия, всё равно опережает любой «по запросу». Внутри группы «по запросу» вперёд выходят
позиции с фотографией. Берётся 5 лучших на каждый раздел и подраздел.

Не менять веса без запроса: они отражают решение заказчика, а не техническое удобство.

### Характеристики: три источника

`allSpecsOf(p)` в `app.js` собирает параметры и помечает происхождение:

1. `каталог Протэк` — из `p.sp`, заполнено примерно у 7% товаров;
2. `сайт <бренд>` — из `p.vsp`, добыто `enrich-vendors.ps1` со строгой сверкой артикула;
3. `из наименования` — разбор названия правилами `SPEC_RULES`, например из
   `TC-C32QN I3/E/Y/2.8mm/V5.1 2Мп Уличная цилиндрическая` достаются разрешение,
   фокус, исполнение и форм-фактор.

Правило: **не добавлять четвёртый источник в виде «правдоподобных» значений.**

Сверка артикула в `enrich-vendors.ps1` — строгая, полным совпадением. `PR08.3940`
и `PR08.39400` это разные изделия; частичное совпадение отбрасывается намеренно.

## Особенности окружения

**PowerShell 5.1 и кириллица.** Файлы `.ps1` с русским текстом обязательно сохранять в
UTF-8 **с BOM**, иначе PowerShell читает их как ANSI и падает с `ParserError`. После любой
правки скрипта:

```powershell
$t=[IO.File]::ReadAllText($f,[Text.UTF8Encoding]::new($false)); [IO.File]::WriteAllText($f,$t,[Text.UTF8Encoding]::new($true))
$err=$null; [void][System.Management.Automation.Language.Parser]::ParseFile($f,[ref]$null,[ref]$err)
```

Зарезервированные имена переменных, которые нельзя присваивать: `$home`, `$pid`, `$host`,
`$input`. При запуске через `-File` массив в параметре приходит одной строкой `"1,2,3"` —
разбирать через `-split ','`.

**Git и gh не в PATH.** Лежат по путям `C:\Program Files\Git\cmd\git.exe` и
`C:\Program Files\GitHub CLI\gh.exe`. Для `gh repo create` нужно временно добавить git
в PATH, иначе gh не видит репозиторий: `$env:PATH = "C:\Program Files\Git\cmd;" + $env:PATH`.

**Доступ к pro-tek.pro.** Сайт закрыт для зарубежных IP. При включённом VPN скрипты выгрузки
не достучатся: TCP-соединение устанавливается, но ответа нет, запрос виснет по таймауту.
Лечится отключением VPN или добавлением `pro-tek.pro` в исключения (split tunneling).
То же касается `iek.ru`, `dkc.ru`, `smartec-security.com` — они пока не обработаны
именно по этой причине.

**Проверка мобильной вёрстки.** Windows не даёт окну Chrome быть уже примерно 500 пикселей,
поэтому `--window-size=390` даёт ложный результат — реально получится 504. Настоящая
мобильная ширина проверяется временной страницей с `<iframe style="width:390px">`.

**Скриншоты через headless Chrome.** Путь проекта содержит пробелы и кириллицу: URL нужно
передавать одним аргументом через `& $chrome ... $url`, иначе Chrome примет его за несколько
адресов и напишет «Multiple targets are not supported». Для страниц с параметрами
(`?id=`) нужен локальный сервер — по `file://` Chrome ищет файл с таким именем целиком.

## Известные ограничения данных

Это ограничения источника, а не выгрузки — их не надо «чинить» подстановкой:

- фотография у товара **одна**, галерей на pro-tek.pro нет ни у одного товара;
- габаритных чертежей, видеообзоров и 3D-моделей нет ни у одной карточки;
- характеристики заполнены у небольшой части позиций;
- «крупное» фото иногда мельче карточного — `build-data.ps1` сравнивает размеры
  и выбирает больший файл;
- у «Промрукав» на сайте производителя тоже одно фото на товар.

## Стиль кода

Комментарии и весь текст интерфейса — по-русски. Комментарий объясняет **почему** так
сделано, а не что делает строка.

Цвета только через токены из `:root`. Фирменные значения взяты из CSS действующего сайта:
`--brand: #005AAB`, `--accent: #E63244`. Подложка — очень светлый небесный `#F4F9FE`.

### Грабли вёрстки, на которые уже наступали

- В сетках на узких экранах использовать `minmax(0, 1fr)`. С обычным `1fr` колонка не может
  стать уже своего содержимого, и страница уезжает по горизонтали.
- Высоту блоков с картинками задавать явно (`height: 430px`), а не через `aspect-ratio`:
  от пропорции не считаются проценты `max-height`, и блок растягивается под снимок.
- Картинки в галерее не растягивать сверх натурального размера (`width: auto`), иначе
  мелкие фото выглядят мыльными.
- Открытие меню по наведению вешать только при `(hover: hover) and (pointer: fine)`.
  На сенсорном экране касание порождает `mouseenter`, следом `click` — меню открывалось
  и тут же закрывалось, приходилось нажимать дважды.
- Анимация появления при прокрутке (`.reveal`) обязана иметь страховку: через 2 секунды
  всё непоказанное принудительно открывается, иначе при сбое наблюдателя контент
  останется невидимым.
- Ссылка с атрибутом `data-open-catalog` раскрывает меню разделов вместо перехода.
  `href` при этом сохраняется рабочим на случай отключённых скриптов.

## Что осталось незакрытым

- IEK, DKC, Smartec не дообогащены — их сайты недоступны из-за VPN.
- Для Dahua и NETLAN нужны отдельные адаптеры в `enrich-vendors.ps1`: у каждого
  производителя своя структура сайта и свой способ поиска по артикулу.
- Репозиторий публичный и содержит логотипы брендов и фотографии товаров производителей.
  Заказчик об этом предупреждён и принял решение осознанно.
